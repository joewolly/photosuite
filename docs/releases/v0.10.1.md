# PhotoSuite v0.10.1

PhotoSuite's first modernized release pairs a classic Photoshop-style desktop workspace with local-assisted selection and editing. PSD/PSB remain the native document formats.

## Highlights

- **Select Subject and Automatic Remove Background:** bundled BiRefNet-lite inference creates a foreground selection or a non-destructive raster mask, without a cloud service.
- **AI-assisted Object Selection:** bundled SAM 2.1 supports positive/negative points and boxes, reusing the source embedding for responsive corrections.
- **Responsive Quick Select:** expensive selection computation runs off the main UI thread.
- **AI Remove:** selected-region inpainting through your local ComfyUI service, with preview before acceptance into an ordinary raster layer.
- **Generative Fill:** optional prompts, up to three sequential variations, and preview/switch/discard/accept controls. Accepted pixels outside the authorized selection remain exact.
- **Generative Expand:** preview a bounded canvas extension, generate only the new exterior, and preserve original interior pixels exactly. Acceptance creates an ordinary raster layer with exact offline Undo/Redo.
- **AI Upscale 4×:** local Real-ESRGAN super-resolution creates a new ordinary raster document, preserving and resizing alpha separately without replacing the source.
- **Optional generation provenance:** accepted Generative Fill layers can carry passive PSD/PSB metadata. Recipes can be disabled; prompts are not saved by default. Opening a file never executes generation, and saved recipes cannot regenerate after reopening because exact selection coverage is not retained.
- **32-bit PSD import repair:** upstream fixes recover layered floating-point PSD content and convert it into the existing RGB8 editing representation, instead of misreading it as flattened content.

## Stability and compatibility

The exact asynchronous transaction architecture keeps generated previews separate from document changes until acceptance. Cancellation, source changes and stale results revoke acceptance; accepted history replays stored pixels without rerunning a model.

This release includes Smart Object/Smart Filter persistence repairs, a Free Transform width-control repair, PSD/PSB persistence validation, and upstream 32-bit PSD and fallback-font license fixes. Hosted JavaScript and Rust CI cover ordinary branch pushes and pull requests. See the [integration audit](https://github.com/joewolly/photosuite/blob/main/docs/modernization-integration-audit.md) and [hosted CI validation](https://github.com/joewolly/photosuite/blob/main/docs/hosted-ci-validation.md) for the recorded evidence and its limits.

The product name remains **PhotoSuite**. This fork now uses **`com.joewolly.photosuite`** as its application identifier, separate from upstream. Application data and plugin directories use the new identifier; existing upstream settings/plugins are not automatically migrated. See the updated [plugin installation paths](https://github.com/joewolly/photosuite/blob/main/docs/PLUGINS.md).

## Local AI setup

| Features | Runtime and model setup |
|:---|:---|
| Select Subject / Automatic Remove Background | Bundled BiRefNet-lite, ONNX Runtime Web/WASM; no extra setup. |
| Object Selection | Bundled SAM 2.1 Hiera Tiny, ONNX Runtime Web/WASM; no extra setup. |
| Quick Select | Built-in worker computation; no model or service. |
| AI Remove | User-managed ComfyUI and a compatible SD 1.5 inpainting checkpoint with CLIP and VAE. |
| Generative Fill / Expand | User-managed ComfyUI 0.37.4 and the reviewed `sd-v1-5-inpainting.ckpt`. |
| AI Upscale 4× | User-managed ComfyUI 0.37.4 and the reviewed `realesr-general-x4v3.pth`. |

AI Remove supports ComfyUI 0.37.0 and 0.37.4. Configure an explicit local loopback endpoint such as `http://127.0.0.1:8188` in Preferences → AI Remove; `http://[::1]:PORT` is also supported. Cloud endpoints and hostnames are unsupported. ComfyUI, Stable Diffusion and Real-ESRGAN are external dependencies, not bundled or downloaded by PhotoSuite. The external service may retain uploads, outputs and prompt history independently of PhotoSuite's metadata preferences.

Setup, hashes, licenses and limits: [subject/background](https://github.com/joewolly/photosuite/blob/main/docs/m3/README.md), [Object Selection](https://github.com/joewolly/photosuite/blob/main/docs/m4/README.md), [AI Remove](https://github.com/joewolly/photosuite/blob/main/docs/m2-local-inpaint.md), [Generative Fill](https://github.com/joewolly/photosuite/blob/main/docs/m6/README.md), [Generative Expand](https://github.com/joewolly/photosuite/blob/main/docs/m8/README.md), [AI Upscale](https://github.com/joewolly/photosuite/blob/main/docs/m5b/README.md), and [generation metadata](https://github.com/joewolly/photosuite/blob/main/docs/m7/README.md).

## Packaging repair

Production builds now recreate a deterministic runtime-only `dist/` before Tauri packaging. The stage follows the HTML entry points, JavaScript module and worker imports, BINDB, and an explicit inventory of dynamic data, bundled ONNX/WASM assets and licenses. It never copies vendor submodule trees. An exact-content verifier rejects missing, altered, unexpected, prohibited or symlinked assets before packaging. Local and hosted builds share this gate; development continues to serve the live source tree.

Staging maps the existing app icon and filter WASM binaries to their already-requested runtime URLs. No product feature, model, vendor source or dependency is upgraded. Git metadata, tests, CI files, build sources, credentials, audit evidence and external checkpoints are excluded.

The historical v0.10.0 tag is unchanged and its release remains draft. v0.10.1 is being prepared without creating a tag or publishing a release.

## Known limitations

- The editor uses **RGB8**. Import conversion does not provide true 16/32-bit editing, HDR preservation or high-bit-depth round trips. PSD/PSB interoperability has documented limits, including the stored white-matted composite for transparency; reopened native layers are validated separately.
- Generative quality depends on the model and image. Review previews carefully, especially text, fine detail and expansion seams.
- Generative Expand is bounded to supported RGB8 raster documents: final dimensions at most **1024 per axis**, at most **512 added pixels per side**, at most **64 layer/group entries** and **16 MiB aggregate source raster/mask/resource backing storage**. Text, vectors, Smart Objects, artboards and other unsupported content are rejected; see the full [support matrix](https://github.com/joewolly/photosuite/blob/main/docs/m8/README.md).
- Bundled WASM models can use substantial memory. The integrated macOS audit observed approximately **3.3 GiB** of editor WebContent memory at peak; worker retirement is not a hard process-memory cap. Exact expansion history also retains pixel snapshots.
- **Artifacts are unsigned and not notarized.** macOS Gatekeeper or Windows SmartScreen may show an additional warning or confirmation before first launch.
- Windows/Linux installers have hosted build evidence, but full native runtime and AI/GPU acceptance remains outstanding.
- Content Security Policy hardening remains future work; the application does not claim to disable all networking.
- Large-model repository storage and reproducible provisioning remain future maintenance work. No new model or dependency upgrade is included in this release-preparation pass.
